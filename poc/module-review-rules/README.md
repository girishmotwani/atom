# Module-local rule-delivery proof

Question: Can a frozen snapshot of the launching module's locally customized Go guidance reach both requested reviewers through Atom's native JSONL review pipeline, with ambient custom instructions still disabled and both responses yielding the known synthetic finding through strict extraction?

Run only after approving the call budget in the POC Brief. From tools, run python ..\poc\module-review-rules\spike.py --scratch <new-session-evidence-directory>. Each invocation may spend two availability probes and two model reviews; it never retries or silently substitutes models.

This disposable Python harness installs the real local instruction bundle into an owned synthetic fixture, customizes and snapshots its Go guide, and mutates both the launch source and review-checkout policy. A process-local composition seam adds the frozen guidance to the unchanged shared rules. The real invocation, Windows lifecycle, JSONL ownership extraction, and findings parser are used.

Existing fixed-evidence isolation excludes tools for the synthetic calls; this does not establish ordinary tool-enabled review behavior. Tiny fixture build/vet are checked separately; the harness skips the full gate pipeline because gate behavior is not this experiment. No production loader, installed package, real project, or live PR is changed.

Raw CLI streams and prompt captures stay in the supplied session directory, outside Git. Only a safe summary belongs in the report. Hashes identify logical pre-transport UTF-8, not exact Windows child-stdin bytes.

The retained source is the separately approved controlled retry: it uses the existing caller-selected exclusions for the two local custom MCP servers and asserts that captured guide bytes match the original trial. Those names are disposable experiment setup, not production defaults. The original timed-out source and both raw trial records remain outside Git; both results are Inconclusive. See the [POC Report](../../specs/module-review-rules/poc-report.md). No further invocation is approved by the presence of this script.

## Historical replay boundary

The guide SHA-256 assertion intentionally identifies the original trial input, not any future bundle revision. This feature updates the bundled Go-guide exposition; building a fixture from the current bundle therefore fails that unchanged assertion before any model calls. Historical replay requires the original trial bundle/frozen input and executed source retained with its evidence, plus a newly approved call budget. Do not remove the assertion, relabel the old verdict, or treat a current-bundle invocation as the original controlled trial. This limitation was checked offline during review; no additional POC calls were made.
